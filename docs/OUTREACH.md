# Contact Outreach — setup and how it works

A learner opens a client scenario, picks a contact, and emails them. Each contact can receive at
most **3 emails per learner**. The contact replies in character, generated by Gemini.

## One-time setup

1. **Gemini key (free).** Create a key at [AI Studio](https://aistudio.google.com/apikey) and add
   `GEMINI_API_KEY=` to the root `.env`, then `pnpm run env:sync`. On Vercel, add the same variable
   (no `NEXT_PUBLIC_` prefix — it is a server secret).
2. **Deploy the rules.** `npx firebase-tools deploy --only firestore:rules` (or merge to `main`
   once the `deploy-rules` workflow has its secrets — see below).
3. **Seed the demo scenario.** `pnpm run seed:outreach`
4. Run `pnpm run dev`, sign in, and open **Client outreach** in the sidebar.

## Where the logic lives

| Concern                                      | File                                                                       |
| -------------------------------------------- | -------------------------------------------------------------------------- |
| 3-email limit, ownership, field validation   | `firebase/firestore.rules` (`isCountedSend`, `isValidOutbound`)            |
| Atomic send (message + counter in one batch) | `frontend/src/features/outreach/lib/sendEmail.ts`                          |
| AI reply (server-only, idempotent)           | `frontend/src/features/outreach/actions/generateReply.ts`                  |
| Prompt building and Gemini call              | `frontend/src/features/outreach/lib/gemini.ts`                             |
| UI                                           | `frontend/src/features/outreach/components/` · `app/(dashboard)/outreach/` |

The limit `3` and the 120 / 2,000 character limits appear in **both** the rules and
`features/outreach/constants.ts` — change both together.

## Tests

| Command                   | What it covers                                                 |
| ------------------------- | -------------------------------------------------------------- |
| `pnpm run test:component` | Validation, send batch, Server Action, UI states (Vitest)      |
| `pnpm run test:rules`     | Security rules against the Firestore emulator — needs Java 11+ |

## CI/CD

- **CI** (`.github/workflows/ci.yml`) runs lint, typecheck, unit tests and the rules tests on every PR.
- **Vercel** builds a preview deployment for every PR and deploys production on merge to `main`.
- **Rules** (`.github/workflows/deploy-rules.yml`) deploy on merge to `main` after the rules tests
  pass. Add repository secrets `FIREBASE_SERVICE_ACCOUNT_KEY_BASE64` and `FIREBASE_PROJECT_ID`.
